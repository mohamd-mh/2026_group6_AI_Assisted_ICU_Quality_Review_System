Two Parallel Pipelines

Baseline vs Modular Workflow

The risk-scoring architecture runs two parallel pipelines over the same processed cases so their outputs can be compared:

1. SIRS-based Baseline
A cited 4-criterion clinical rule (Bone et al., 1992): temperature, heart rate, respiratory rate, and white blood cell count. This baseline replaced an earlier set of 10 ad-hoc, uncited rules used in an early prototype.
2. Modular Agent-Inspired Workflow
Five sequential stages: Data Validator → Baseline Scorer → Weighted Clinical Assessor (APACHE II/SOFA-inspired, using uncalibrated engineering-judgment weights, not a validated clinical score) → Verifier (escalates risk upward only, never downward) → Explainer.
Honest Scope

Agent-Inspired Workflow

The modular workflow is implemented as a deterministic, rule-based sequential pipeline of specialized components. It is not a full autonomous AutoGen-style multi-agent negotiation system, and there is no LLM call anywhere in the risk-scoring path. This is intentional for a safer academic prototype: each component has a clear responsibility and its output can be inspected.

Review Queue Flow

Workflow

Open queue or case library. The coordinator selects existing review work or adds a dataset case.

Run AI-supported review. The workbench produces risk probability, risk level, screening context, explanation, similar cases, anomaly context, and uncertainty.

Prepare review handoff. The coordinator reviews the generated Review Ticket and Prepared Review Summary for the Quality & Patient Safety Review Team.

Document review status. The coordinator sets status, priority, assigned reviewer, and notes.

Preserve traceability. Audit events record changes for review history and follow-up.
