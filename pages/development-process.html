Development Process

From Prototype to AI-Assisted Review System

The project evolved from a baseline ICU risk prototype into a role-focused quality review information system with real ML methods, explainability, workflow documentation, and auditability.

Process

Major Steps

Initial baseline prototype. The early version focused on ICU risk scoring and simple comparison outputs.

Baseline correction. An original set of 10 ad-hoc, uncited rules was replaced with the 4 cited SIRS criteria (Bone et al., 1992) as the baseline pipeline.

Modular agent-inspired workflow. The project added specialized components for validation, risk assessment, verification, explanation, and traceability. This is a deterministic, rule-based pipeline, not a full autonomous AutoGen-style multi-agent negotiation system.

Faculty feedback. Feedback identified that the project needed clearer AI content and a clearer real-world user.

Expanded dataset. The data basis was expanded to 1000 processed ICU stays.

Real ML training. A supervised ML model was trained and saved with metadata, metrics, thresholds, and feature importance.

Additional AI support. Explainability, KNN similar-case retrieval, KMeans clustering, IsolationForest anomaly detection, and uncertainty estimation were added.

Information-system features. The system added review queue, manual case entry, notes, status, priority, archive behavior, and audit history.

Role alignment and UI simplification. The target user became the ICU Quality & Patient Safety Coordinator, and the interface was simplified around review work.

Challenges

Engineering Challenges

  • MIMIC data size and raw-file handling.
  • Preprocessing and missing values.
  • Class imbalance in the target label.
  • Avoiding clinical overclaiming.
  • Separating the website from the runnable software system.
  • Keeping the submitted workbench local, traceable, and safely scoped for academic review support.
Lessons

Lessons Learned

  • Real AI must be traceable and grounded in data.
  • Workflow matters as much as model output.
  • Medical AI prototypes need safe scope and explainability.
  • Documentation should clearly distinguish academic review support from clinical deployment.
  • Naming matters: an early "planning-driven multi-agent LLM workflow, inspired by LPW and AutoGen" description overclaimed the system. The corrected description — a modular, agent-inspired workflow, not a full autonomous AutoGen-style multi-agent negotiation system — matches what actually runs: a deterministic rule-based pipeline with no LLM call anywhere in the risk-scoring path.
  • Uncited, ad-hoc baseline rules should be replaced with a cited clinical reference standard (SIRS) to give the comparison a defensible baseline.
